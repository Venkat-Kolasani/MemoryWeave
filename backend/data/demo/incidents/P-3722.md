## Root Cause

payment-worker pods OOMKilled under sustained webhook traffic. Memory limits set during initial launch never updated for 3× traffic growth. Redis connection pool on payment-api contributed secondary latency.

## Exact Resolution Steps

1. `kubectl get pods -n prod -l app=payment-worker` — multiple OOMKilled.
2. `kubectl rollout restart deploy/payment-worker -n prod`.
3. Inspected metrics: memory usage pegged at limit, CPU moderate.
4. `kubectl set resources deployment/payment-worker --limits=memory=768Mi --requests=memory=512Mi`.
5. Scaled HPA: `kubectl patch hpa payment-worker-hpa --patch '{"spec":{"maxReplicas":10}}'`.
6. Verified Redis: `redis-cli -u $REDIS_URL INFO clients` — connection count normalized.
7. Confirmed Stripe webhook processing rate returned to baseline.
8. No billing DB intervention required this incident.
