## Root Cause

Clock skew on auth-service Kubernetes nodes caused JWT validation to reject otherwise valid refresh tokens. Unrelated to payment-api outage patterns but caused secondary customer login friction during peak traffic.

## Exact Resolution Steps

1. Checked auth-service logs: `invalid token: iat in the future` on pods `auth-service-7f8b-*`.
2. Ran `kubectl exec` → `chronyc tracking` on affected pods — offset > 30 seconds.
3. Cordoned nodes, drained auth-service pods, forced reschedule onto synced nodes.
4. Rotated signing keys (kid `prod-2024-03`) and invalidated stale refresh tokens.
5. Verified payment-api → auth-service dependency: token refresh latency restored.
6. Updated monitoring: alert on NTP drift > 5s for auth-service node pool.

## Systems Affected

- **Auth Service** (auth-service deployment, JWT issuer)
- **Payment API** (downstream — elevated refresh latency, no direct outage)
- **Data Bus** (Kafka auth events briefly delayed)
